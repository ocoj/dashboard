## i18n 架构说明（v2 — 解耦设计）

### 为什么换架构？

旧方案依赖 `next-intl`，翻译调用散落在 236 个组件文件中。上游 force-push 或大规模重构会导致所有 `t()` 调用丢失，需要从零汉化。

新方案采用**翻译层与源码分离**的设计：

```
上游源码（236 个 .tsx）      翻译层（独立维护）
─────────────────────      ──────────────────
"Add Peer"  ←──映射──→   "添加节点"
"Delete"    ←──映射──→   "删除"
...                         ...

通过 <TransText> 组件在运行时自动查找翻译，
翻译层修改不影响上游代码，上游更新不破坏翻译层。
```

### 核心组件

| 文件 | 作用 | 上游有吗？ |
|------|------|-----------|
| `src/i18n/messages/en.ts` | 英文翻译源（命名空间结构） | ❌ 我们的 |
| `src/i18n/messages/zh.ts` | 中文翻译源（命名空间结构） | ❌ 我们的 |
| `src/i18n/trans-map.ts` | 自动生成的 English→Chinese 平面 Map | ❌ 我们的 |
| `src/i18n/trans-text.tsx` | `<TransText>` 翻译组件 | ❌ 我们的 |
| `src/i18n/locale-context.tsx` | 语言环境 Provider + useLocale hook | ❌ 我们的 |
| `src/components/ui/LocaleSwitcher.tsx` | 语言切换按钮 | ❌ 我们的 |
| `src/layouts/AppLayout.tsx` | 包裹 LocaleProvider（仅 2 行改动） | ✅ 上游有 |
| `src/modules/settings/LanguageTab.tsx` | 设置页语言选项（改动约 5 行） | ✅ 上游有 |

### 翻译工作流

```
新增翻译只需两步：

1. 在 en.ts 和 zh.ts 中新增对应条目：
   common: {
     addPeer: "Add Peer",        // en.ts
     addPeer: "添加节点",        // zh.ts
   }

2. 重新生成 trans-map.ts：
   node scripts/build-trans-map.js

3. 在组件中使用：
   import { TransText } from "@/i18n/trans-text";
   <Button><TransText>Add Peer</TransText></Button>
```

### 禁止行为（红线）

| ❌ 禁止 | ✅ 正确做法 |
|---------|------------|
| 在 .tsx 中硬编码中文字符串 | 用 `<TransText>` 包裹英文原文 |
| 用 Python 脚本序列化翻译文件 | 用 `sed` 直接插入，或用编辑器 |
| 修改 `trans-map.ts`（会被覆盖） | 修改 en.ts / zh.ts，然后 `node scripts/build-trans-map.js` |
| 删除上游组件的原有文本 | 在原文本外包 `<TransText>`，保留英文原文作为 fallback |

## 标准工作流（严格按此顺序执行）

---

### 第 0 阶段：前置准备

1. 阅读踩坑记录 `i18n/README.md`，避免已知问题
2. 熟记术语表 `i18n/TERMS.md`，保持翻译一致性
3. 确认本地开发环境正常：
   ```bash
   npx tsc --noEmit
   ```

---

### 第 1 阶段：安全检查 + 获取上游更新

> ⚠️ **此阶段为 v2 新增，必须执行，不可跳过。**

1. 切换到 `i18n-clean` 分支，确保工作区干净
2. 获取上游最新代码：`git fetch netbirdio`
3. **运行安全检查脚本**：
   ```bash
   bash scripts/sync-check.sh
   ```
   - 脚本自动检测 force-push、评估变更量
   - 退出码 0 → 正常同步，继续
   - 退出码 1 → force-push 检测到，会在下一步用不同策略

4. 查看差异摘要：
   ```bash
   git log --oneline i18n-clean..netbirdio/main | head -20
   git diff --stat i18n-clean..netbirdio/main | tail -5
   ```
5. **无新提交** → 终止，报告"上游无更新"
6. **有新提交** → 记录变更摘要（涉及的文件范围、新增组件、新功能点），继续下一步

---

### 第 2 阶段：保存 i18n → 合并上游 → 恢复 i18n

> ⚠️ **v2 新流程**：合并前保存翻译层，合并后自动恢复，避免丢失。
>
> **根据 sync-check 的结果分两条路径：**

**路径 A：正常同步（sync-check 退出码 0）**

```bash
# Step 1: 保存 i18n 状态（预防万一）
bash scripts/sync-save-i18n.sh

# Step 2: 正常合并
git merge netbirdio/main --no-edit

# Step 3: 恢复 i18n 状态
bash scripts/sync-restore-i18n.sh
```

**路径 B：force-push 检测（sync-check 退出码 1）**

```bash
# Step 1: 保存 i18n 状态
bash scripts/sync-save-i18n.sh

# Step 2: 强制取上游（merge base 退化，所有冲突取 theirs）
git merge netbirdio/main -X theirs --no-edit

# Step 3: 恢复 i18n 独立文件
bash scripts/sync-restore-i18n.sh

# Step 4: 检查并修复上游文件中的 TransText 包裹
# force-push 会覆盖 AppLayout、LanguageTab 等上游文件中的 TransText 改动
# 手动检查并恢复以下文件中的 i18n 改动：
#   - src/layouts/AppLayout.tsx → 添加 LocaleProvider import + 包裹
#   - src/modules/settings/LanguageTab.tsx → 改用 locale-context + TransText
#   - 其他已汉化的上游文件（通过 git diff 检查）
```

**路径 B 的恢复检查清单：**

```bash
# 检查 AppLayout 是否有 LocaleProvider 包裹
grep -q "LocaleProvider" src/layouts/AppLayout.tsx && echo "✓" || echo "✗ 需手动恢复"

# 检查 LanguageTab 是否改用新 context
grep -q "locale-context" src/modules/settings/LanguageTab.tsx && echo "✓" || echo "✗ 需手动恢复"

# 列出所有已使用 TransText 但可能被覆盖的文件
git diff --name-only HEAD~1 -- '*.tsx' | xargs grep -l "TransText" 2>/dev/null
```

如果 `sync-restore-i18n.sh` 报告冲突：
- 独立文件（LocaleSwitcher、trans-map 等，上游没有的）→ 取我们的版本
- AppLayout/LanguageTab（上游也有的）→ 手动合并，改动很小（2-5 行）

---

### 第 3 阶段：全面汉化增量内容（核心环节）

> 本阶段严格遵循：**浏览器遍历 → 代码扫描定位 → 执行汉化 → 代码复查**

#### 3a. 浏览器遍历 — 记录所有英文文本

> ⚠️ **本步骤必须在真机/浏览器上完成，不可跳过。**

1. 启动本地开发服务器 `npm run dev`，或部署到 OMV（第 6 阶段）
2. 打开 `https://nb.lanxun.pro:30443`（或 localhost:3000），强制刷新
3. 切换到中文（右上角地球图标 → 选择「中文」）
4. **逐菜单遍历**新增/变更的功能页面：
   - 点开每个子页、按钮、Tab、弹窗
   - 弹窗内每个 Tab 都要点击
   - 多步向导推进到每一步
   - Tooltip、placeholder、下拉选项都要检查
5. **记录所有仍然显示英文的文本**，形成完整清单

#### 3b. 代码扫描定位

1. 列出本次合并新增/修改的 `.tsx` 文件：
   ```bash
   git diff --name-only --diff-filter=AM HEAD -- '*.tsx'
   ```
2. 对每个文件，搜索硬编码英文文本（JSX children）：
   ```bash
   grep -rn '>[A-Z][a-z]' <文件路径> | grep -v 'className\|href\|TransText\|//'
   ```
3. 对照浏览器遍历的记录清单，逐一定位源文件和行号

#### 3c. 执行汉化

**使用 `<TransText>` 组件包裹英文文本：**

```tsx
// 改造前（硬编码英文）
<Button>Add Peer</Button>
<h1>Network Settings</h1>
<Label>Operating System</Label>

// 改造后（TransText 包裹）
import { TransText } from "@/i18n/trans-text";

<Button><TransText>Add Peer</TransText></Button>
<h1><TransText>Network Settings</TransText></h1>
<Label><TransText>Operating System</TransText></Label>
```

**如果翻译 Map 中不存在该文本，需要往 en.ts/zh.ts 添加：**

```ts
// en.ts — 在合适的命名空间中添加
common: {
  addPeer: "Add Peer",
}

// zh.ts — 同样位置添加中文
common: {
  addPeer: "添加节点",
}
```

添加后重新生成 trans-map：
```bash
node scripts/build-trans-map.js
```

**翻译规范：**
- 中文引号用「」，避免 TS 字符串中转义
- 参考 `i18n/TERMS.md` 术语表
- 保持与已有翻译风格一致

#### 3d. 代码复查

1. TypeScript 编译检查：`npx tsc --noEmit`
2. 对本次涉及的组件目录，做硬编码英文兜底搜索：
   ```bash
   git diff --name-only HEAD -- '*.tsx' | xargs -I{} grep -l '>[A-Z][a-z]' {} | grep -v TransText
   ```
3. 复查清单：
   - [ ] 所有用户可见文本是否已用 `<TransText>` 包裹？
   - [ ] `en.ts` 和 `zh.ts` 是否同步新增了对应条目？
   - [ ] `trans-map.ts` 是否重新生成？
   - [ ] 组件中是否有残留的硬编码字符串？
   - [ ] `npx tsc --noEmit` 是否零错误通过？

### 第 5 阶段：发布新版本

1. 确认上游版本号：
   ```bash
   # 优先从 tag 获取
   git describe --tags netbirdio/main --abbrev=0 2>/dev/null || \
   # 无 tag 时用最新 tag + commit 数
   git describe --tags netbirdio/main 2>/dev/null || \
   # 兜底：直接用日期
   echo "v$(date +%Y%m%d)"
   ```
2. 版本号格式：上游版本 + `-zh`，如 `v2.90.5-zh`
3. 更新 `CHANGELOG.md`，记录本次同步的变更摘要
4. 创建 Git tag 并提交推送：
   ```bash
   git add -A
   git commit -m "sync: 同步上游至 <UPSTREAM_VER> + 汉化"
   git push origin i18n-clean
   git tag <VER>-zh
   git push origin <VER>-zh
   ```
5. GitHub Actions 自动构建 Docker 镜像：
   - Push tag → `ghcr.io/ocoj/dashboard:<VER>-zh`
   - Push i18n-clean → `ghcr.io/ocoj/dashboard:latest`

## 安全红线

- 所有密码/Token 必须通过 Vaultwarden MCP 获取，禁止硬编码或存本地
- OMV 只执行 `pull` + `up -d`，禁止修改任何配置文件

## 常见踩坑速查

| 坑 | 对策 |
|----|------|
| **force-push 合并** | 使用 `scripts/sync-check.sh` 检测 + `sync-save-i18n.sh` / `sync-restore-i18n.sh` |
| 合并后 i18n 文件消失 | 运行 `sync-restore-i18n.sh` 自动恢复 |
| 反斜杠加倍 | 禁止 Python 序列化翻译文件，用 `sed` 直接插入 |
| 翻译 Map 过期 | 修改 en.ts/zh.ts 后运行 `node scripts/build-trans-map.js` |
| 浏览器缓存 | 部署后 Ctrl+Shift+R 强制刷新 |
| TransText 不翻译 | 检查 trans-map.ts 是否有该英文条目，没有则往 en.ts/zh.ts 新增 |
